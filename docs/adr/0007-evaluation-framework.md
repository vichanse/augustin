# ADR 0007: Bug-fixing evaluation framework

Status: Proposed

## Context

The harness verification of ADR 0006 tells the user whether one test command passed after the last edit. It is not a measure of whether Augustin fixes bugs: the visible tests may be incomplete, and the harness trusts the workspace it runs in. Milestone M1.10 adds an independent measurement, and closes the M1.6 gap of an opt-in real-model run.

## Decision

- **Reuse, no parallel framework.** The `evals` package (already the home of the deterministic scenarios) now holds the dataset, runner, evaluator, approver and report; `cmd/augustin-eval` is a thin CLI. Attempts use the production pieces: `internal/prompt` (system prompt and tool definitions, moved out of `cmd/augustin` so both share them), `tools.Registry` with the real read, edit and command preparers, `agent.Loop` with `ReserveFinalResponse` and the verification gate, and `verification.Tracker`.
- **Dataset.** Five bug-fixing cases (`discount`, `pagination`, `nil-pointer`, `multi-file`, `regression-trap`) and a read-only `smoke-readonly` case, each a tiny standard-library Go module described by `evals/cases/<id>/case.json`: ID, description, prompt (behaviour, not the fix), fixture, hidden tests, allowed paths, expected baseline failure and timeout. Files are stored as `.txt` and embedded with `go:embed`, so neither buggy code nor hidden tests are part of this repository's build. `DatasetVersion` is bumped by hand when cases change; `DatasetHash` identifies the exact bytes.
- **Lifecycle per attempt.** A fresh temporary directory; the fixture is copied in; a copy proves the baseline fails with the expected message (otherwise `infrastructure_error`, and the agent does not run); the agent runs in the workspace with a fresh provider and no shared history; the final workspace is snapshotted and copied for evaluation; everything is removed afterwards. Nothing runs against the Augustin repository or a user workspace.
- **Independent evaluator.** The verdict ignores the answer, the model's claims, the harness verification status and the shape of the code. It compares the final workspace with the original fixture: any change outside the allowed paths, or any added or deleted file, is a `policy_violation`, whatever produced it. It then runs `go test ./...` on a copy (visible tests), adds the hidden tests to that copy only, and runs the suite again. A case is `resolved` only if the baseline failed as expected, both runs pass, nothing unauthorized changed, and the agent run and the evaluator completed. Any implementation that passes is accepted. The read-only smoke case is resolved when the run completes, reads the workspace and changes nothing.
- **Evaluation-only approval.** `evals.Approver` approves only edits to a case's allowed source files (never tests or `go.mod`) and only `go test`, `go vet` and `go build ./...`; everything else is rejected and counted. It goes through the normal `tools.Policy` (`ExecutePolicy`), so authorization and evidence are unchanged. The runner constructs it explicitly; no environment variable or CLI mode enables it, and a test checks that `cmd/augustin` does not depend on the `evals` package.
- **Outcomes**, in precedence order: `infrastructure_error` (broken baseline, toolchain or evaluator), `policy_violation`, `provider_error`, `timeout` (case timeout or total duration), `budget_exhausted`, then `resolved` or `unresolved`. Infrastructure errors are reported separately and excluded from the resolution-rate denominator, which the summary states.
- **Metrics** per attempt: case, scenario, attempt number, outcome, harness verification, visible and hidden results, modified and unauthorized files, approved and rejected actions, iterations, tool calls, input and output tokens (from provider responses, through the loop's metadata events), verification attempts, agent, evaluation and total durations, and a cost only when prices are passed explicitly. The report adds schema, Augustin version, dataset version and hash, mode, provider, model, budgets and start time. No prompt, code, diff, tool output or credential is stored.
- **Two modes.** Deterministic (default, `make eval`, and the tests run by `go test ./...`): scripted scenarios per case, with expected outcomes, including a wrong fix, a false success claim, an attempt to edit a test and a superficial fix that passes the visible tests only; no network and no API key. Real (`--mode real`, `make eval-real`): the existing provider configuration with `AUGUSTIN_ALLOW_REMOTE_DATA=true`, sequential, one attempt per case by default, `--repeat`, a total `--max-duration`, existing per-turn budgets, and Ctrl+C stops cleanly with partial results. `make check` never runs it.

## Consequences

- **Not an OS sandbox.** Temporary directories and tool restrictions do not isolate project code: the agent's `go test`, and the evaluator's, run the fixture code as modified by the model, with the user's privileges, file system and network. Run real-model evaluations only in a disposable, restricted environment without unrelated credentials or sensitive files reachable by subprocesses. Subprocesses get a minimal environment (`GOPROXY=off`, `GOTOOLCHAIN=local`, no `GOFLAGS`, no provider credentials).
- **Reproducibility.** Deterministic results are reproducible. Real-model results vary between runs and provider versions; use `--repeat` and compare reports with the same dataset hash, Augustin version and budgets.
- **Small dataset.** Five cases measure the foundation, not general bug-fixing ability; prompts and fixtures are known in this repository and may leak into model training over time.
- Hidden tests can only reject what they check: a solution that passes them but breaks other behaviour counts as resolved.
- Timing includes `go test` compilation and depends on the build cache.
